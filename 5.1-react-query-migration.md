# React Query Migration Plan

## Goal

Replace Context-based data fetching (`useSettings`) with React Query hooks for:

- Automatic caching (no duplicate API calls)
- Better performance
- Simpler code

---

## React Query Hooks Available

```typescript
// Users
const { data: users = [], isLoading } = useUsersQuery();

// Tasks
const { data: tasks = [], isLoading } = useTasksQuery();

// Tags
const { data: primaryTags = [] } = usePrimaryTagsQuery();
const { data: secondaryTags = [] } = useSecondaryTagsQuery();

// Contacts
const { data: contacts = [] } = useContactsQuery();

// History
const { data: history = [] } = useAllTasksHistoryQuery();
```

## After Migration

### Delete These Context Files

- `contexts/UsersContext.tsx`
- `contexts/TasksContext.tsx`
- `contexts/TagsContext.tsx`
- `contexts/ContactsContext.tsx`
- `contexts/HistoryContext.tsx`

### Simplify SettingsContext

Keep only `SettingsProvider` as a thin wrapper for any remaining shared state, or remove entirely.

---

## WebSocket Integration

Keep the socket integration in `api/queries/socketIntegration.ts`:

- `invalidateTaskQueries()` - called on task socket events
- `invalidateUserQueries()` - called on user socket events
- etc.

This ensures real-time updates still work with React Query.
