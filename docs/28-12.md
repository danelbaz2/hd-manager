## ⚡ Performance Improvements Needed

### Backend Improvements

| Issue                     | Impact                        | Solution                                                                  |
| ------------------------- | ----------------------------- | ------------------------------------------------------------------------- |
| **No MongoDB Indexes**    | Slow queries                  | Add indexes on `username`, `base.isDeleted`, `date`, `responsibleUserIds` |
| **N+1 Query in JWT**      | DB hit on every request       | Cache user data or refresh tokens                                         |
| **Full Document Fetches** | Memory overhead               | Use MongoDB projections                                                   |
| **No Pagination**         | Memory issues with large data | Implement `skip`/`limit` pagination                                       |

### Frontend Improvements

| Issue                        | Impact                | Solution                      |
| ---------------------------- | --------------------- | ----------------------------- |
| **Loading All Data at Once** | Slow initial load     | Lazy loading / code splitting |
| **No Request Caching**       | Redundant API calls   | React Query or SWR            |
| **Full Data Re-fetches**     | Unnecessary bandwidth | Incremental updates           |

## 🔌 Recommended Future Enhancements

### WebSockets for Real-Time Updates

- **Why:** Current polling requires manual refresh; User A's changes aren't visible to User B
- **Benefits:** Instant sync, presence awareness, collaboration features
- **Recommendation:** Flask-SocketIO + MongoDB Change Streams

### Virtual Scrolling

- **Why:** All tasks/users/history loaded at once causes performance issues
- **Benefits:** Constant memory usage, smooth 60fps scrolling, fast initial render
- **Recommendation:** `@tanstack/react-virtual` for lists with 200+ items
