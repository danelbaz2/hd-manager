## 🔐 1. JWT Authentication System

### Overview
Implemented a complete JWT (JSON Web Token) authentication system with role-based access control.

### Changes Made

#### Backend
| File | Change |
|------|--------|
| `utils/jwt_utils.py` | New JWT utility functions (generate, validate, decode) |
| `routes/auth.py` | Enhanced with `/me` endpoint, JWT token generation |
| `.env.example` | Added JWT_SECRET_KEY configuration |
| `requirements.txt` | Added `pyjwt` dependency |

#### Frontend
| File | Change |
|------|--------|
| `contexts/AuthContext.tsx` | New context for authentication state management |
| `api/authApi.ts` | Auth API functions (login, logout, getCurrentUser) |
| `components/auth/ProtectedRoute.tsx` | Route protection with auth check |
| `components/auth/LoginTransition.tsx` | Animated login flow component |
| `pages/login-page/LoginPage.tsx` | Enhanced login UI with loading states |

### Technical Details

```typescript
// JWT Token Flow
1. User logs in → Server generates JWT (7-day expiry)
2. Token stored in sessionStorage
3. All API requests include Authorization header
4. /api/auth/me endpoint validates token and returns user data
```

```python
# JWT Configuration
JWT_SECRET_KEY = "your-secret-key"
JWT_EXPIRY_DAYS = 7
JWT_ALGORITHM = "HS256"
```

### Role-Based Access Control
- **Admin users**: Full access to all features
- **Regular users**: Limited access (no Settings, no Create Task button)

### Benefits
- ✅ Stateless authentication
- ✅ Secure token-based sessions
- ✅ Role-based UI rendering
- ✅ Automatic token refresh support (future)

## 📊 2. Model Refactoring

### Overview
Cleaned up data models by removing redundant fields and standardizing naming conventions.

### Changes Made

#### Removed `lut` Field
The `lut` (Last Update Time) field was redundant with `updatedAt`. It has been removed from:

| Model | Change |
|-------|--------|
| `BaseEntityMeta` | Removed `lut` field |
| `HistoryEntryModel` | Removed `lut` from history logging |
| All routes | Updated to use `updatedAt` instead |

**Before:**
```python
class BaseEntityMeta(BaseModel):
    isDeleted: bool = False
    createdAt: int
    updatedAt: int
    lut: int  # REDUNDANT - removed
    entityType: str
```

**After:**
```python
class BaseEntityMeta(BaseModel):
    model_config = ConfigDict(extra='forbid')
    isDeleted: bool = False
    createdAt: int
    updatedAt: int  # Single source of truth
    entityType: str
    isActive: bool = True
    createdBy: Optional[str] = None
    updatedBy: Optional[str] = None
```

#### Field Renaming
| Old Name | New Name | Reason |
|----------|----------|--------|
| `responsibleUsersId` | `responsibleUserIds` | Plural consistency |

### Migration Impact
- **Breaking Change**: API consumers must update to use new field names
- **Database**: Existing documents with `lut` field are backward compatible (ignored)

2. **Optimistic UI Updates**
   - Immediate visual feedback on status change
   - Background API sync
   - Automatic rollback on error

3. **Task Sorting**
   - Tasks sorted by `updatedAt` timestamp
   - Newest tasks appear at bottom of columns

### Code Example
```tsx
// Optimistic UI pattern
const handleTaskStatusChange = useCallback(async (taskId, newStatus) => {
  // 1. Optimistic update
  setOptimisticTasks(prev => 
    prev.map(t => t.id === taskId ? { ...t, status: newStatus } : t)
  );
  
  // 2. API call
  await updateTask(taskId, { status: newStatus });
  
  // 3. Sync with server
  refreshTasks();
}, []);
```

## 🏷️ 4. Two-Tier Tag System

### Overview
Implemented a hierarchical tag system with primary and secondary tags.

### New API Endpoints

| Endpoint | Method | Description |
|----------|--------|-------------|
| `/api/primary-tags` | GET | Get all primary tags |
| `/api/primary-tags` | POST | Create primary tag |
| `/api/primary-tags/<id>` | PUT | Update primary tag |
| `/api/primary-tags/<id>` | DELETE | Delete primary tag |
| `/api/secondary-tags` | GET | Get all secondary tags |
| `/api/secondary-tags` | POST | Create secondary tag (requires primaryTagId) |
| `/api/secondary-tags/<id>` | PUT | Update secondary tag |
| `/api/secondary-tags/<id>` | DELETE | Delete secondary tag |

### Data Structure

```python
# Primary Tag
{
    "id": "string",
    "name": "string",
    "color": "#RRGGBB",
    "description": "string (optional)",
    "base": BaseEntityMeta
}

# Secondary Tag
{
    "id": "string",
    "name": "string",
    "primaryTagId": "string",  # Reference to parent tag
    "description": "string (optional)",
    "base": BaseEntityMeta
}
```

### Frontend Integration
- `SettingsContext` updated with `primaryTags` and `secondaryTags`
- New `TwoTierTagsSelect` component for tag selection
- Contacts now use `primaryTagIds` for categorization

## ⚡ 5. Unified Global Loader

### Overview
Created a single, beautiful loading component used across the entire application.

### New Component
**File**: `components/global-loader/GlobalLoader.tsx`

### Features
- 🎨 Animated background orbs with gradient blur
- ✨ Glowing logo/icon with smooth rotation
- 🔵 Three bouncing dots with staggered animation
- 📝 Gradient text for loading message
- 📊 Shimmer progress bar
- 🌙 Dark mode support

### Props Interface
```typescript
interface GlobalLoaderProps {
  text?: string;        // Default: "טוען..."
  subtext?: string;     // Optional additional text
  fullScreen?: boolean; // Default: true
  className?: string;   // Additional CSS classes
}
```

### Architecture Change
**Before**: Multiple loaders in different components
- ProtectedRoute had its own loader
- HomePage had DelayedLoader
- TaskPage had its own loader
- LoginTransition had separate loading UI

**After**: Single unified loader
- `ProtectedRoute` now waits for BOTH auth AND data loading
- All pages render only when fully loaded
- `LoginTransition` uses `GlobalLoader` for loading state

### Usage
```tsx
// Full screen loader (default)
<GlobalLoader />

// With custom text
<GlobalLoader text="טוען משימות" subtext="אנא המתן..." />

// Inline loader
<GlobalLoader fullScreen={false} />
```

## 🔒 7. Security Improvements

### Password Hash Protection
- `passwordHash` field removed from all GET responses
- Users cannot update passwords via regular PUT endpoint
- Dedicated password change endpoint (if needed)

### Implementation
```python
# In routes/users.py
def get_all_users():
    users = list(mongo.db.ents.find(...))
    for user in users:
        user.pop('passwordHash', None)  # Remove sensitive data
    return jsonify(users)
```
