# React Query Redundancy Diagnostic Report

**Date:** 2026-01-05 (Morning)

---

## 🔎 Diagnostic Summary: React Query Redundancy

### The Problem: Dual State Management

You currently have **two parallel systems** for managing the same data:

1. **`SettingsContext.tsx`**: Fetches and stores data in React state (`users`, `tasks`, `taskHistory`, etc.) using raw API calls (`getAllUsers()`, `getAllTasks()`).
2. **React Query (`*Queries.ts`)**: Also fetches the same data using `useQuery` hooks (`useUsersQuery`, `useTasksQuery`).

**This causes duplicate API requests** because both systems attempt to fetch data independently.

---

## Identified Issues

| #   | Issue                                    | Location                             | Impact                                                                                                                                       |
| :-- | :--------------------------------------- | :----------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | **Duplicate Fetching**                   | `SettingsContext` + `useTasksQuery`  | Same `/api/tasks` called twice on mount                                                                                                      |
| 2   | **Mutation → Invalidate → Refetch Loop** | `taskQueries.ts` lines 119, 140, 165 | After create/update/delete, `invalidateQueries` triggers a full refetch, _even though_ `SettingsContext` already updates state via WebSocket |
| 3   | **Double Invalidation on WebSocket**     | `SettingsContext.tsx` lines 456, 493 | WebSocket update _already_ updates local state, but then `invalidateTaskQueries()` is called, causing another API fetch                      |
| 4   | **`refetchOnWindowFocus: true`**         | `queryClient.ts` line 17             | Every time the window regains focus, React Query refetches all stale queries, even if WebSocket has already provided fresh data              |
| 5   | **`staleTime` too short**                | `queryClient.ts` line 11 (2 min)     | Data is marked stale quickly, leading to frequent refetches                                                                                  |

---

## Recommended Fixes

| #   | Fix                                                                                                                                  | Effect                                     |
| :-- | :----------------------------------------------------------------------------------------------------------------------------------- | :----------------------------------------- |
| 1   | **Remove `SettingsContext` data fetching for tasks/users.** Use React Query as the single source of truth.                           | Eliminates duplicate fetches               |
| 2   | **Replace `invalidateQueries` in mutations with `setQueryData`.** Update cache directly with the API response instead of refetching. | Eliminates post-mutation refetch           |
| 3   | **On WebSocket update, use `setQueryData` instead of `invalidateQueries`.**                                                          | Eliminates refetch after WebSocket push    |
| 4   | **Set `refetchOnWindowFocus: false`** in `queryClient.ts`.                                                                           | Prevents unnecessary refetch on tab switch |
| 5   | **Increase `staleTime` to 5+ minutes** in `queryClient.ts`.                                                                          | Reduces refetch frequency                  |

---

## Quick Win (Smallest Change, Big Impact)

If you don't want to refactor the entire `SettingsContext`, the easiest **immediate improvement** is:

### Changes to Apply:

1. **Turn off `refetchOnWindowFocus`** in `queryClient.ts`:

   ```typescript
   refetchOnWindowFocus: false,
   ```

2. **Remove redundant `invalidateQueries` calls** from `SettingsContext.tsx`:

   - Remove line 456: `invalidateTaskQueries();`
   - Remove line 493: `invalidateUserQueries();`

   _Reason: The WebSocket handler already updates local state directly. Calling `invalidateQueries` afterward triggers an unnecessary API refetch._

3. **Increase `staleTime`** in `queryClient.ts` from 2 minutes to 5 minutes:
   ```typescript
   staleTime: 5 * 60 * 1000, // 5 minutes
   ```
